## Design as implemented

Exact mode is an opt-in `timing_mode="exact"` on `generate_clip` and the internal `create_clip` bridge; absence or `"legacy"` keeps every existing behaviour and the existing result shape, and the legacy planning block is byte-identical apart from being nested under `else`. `preserve_timing` is not repurposed. The new `backend/services/exact_render.py` holds the validation, time mapping, probing and verification helpers; the renderer calls them at the decision points.

- **B1-1.** `keep_segments` must be a nonempty list of objects with finite numeric `start`/`end`, positive duration, `start >= 0` and `end` within the probed source duration (1 ms slack). Validated copies are used; nothing is sorted, merged, widened, clamped or dropped, and backward source order is cut as given. `cut_multi_segment` is used for one interval as for many. Weak-opening trim, sentence-end extension, automatic pause/filler cuts, boundary revert and the transition autofix pass (including its environment override) are all bypassed; `trim_opening` and `preserve_timing` are ignored. `clean_fillers` only removes filler words from the drawn captions. `start_second`/`end_second` are ignored for cutting and reported back as the bounding min/max of the intervals. Audio-only sources are refused with an explicit unsupported-mode error before the audiogram branch, which stays available to legacy calls. Supplied logo/intro/outro paths must exist. All rejections happen before the work directory exists.
- **B1-2.** `render_timeline` version 1 carries: time-domain descriptions; source probe (duration, fps, variable-rate flag, dimensions, audio presence); `segments[]` with source-absolute bounds and content-relative placement in output order; requested and measured content duration; `content_to_output_offset`; probed `output_duration` and per-stream `output` measurements; the tolerance actually applied and its basis; a frame-precision note; bookend regions with the helper's real branch and overlap; an explicit `thumbnail_card.applied: false` note; framing (format, dims, strategy, foreground framing, keyframes with `time_domain: "content"`); `words` with `input: "supplied" | "unavailable"`, the retained source-absolute words touching any interval, the derived content-relative boundary-clipped words in output order and their text; `captions` with requested/rendered/renderer (`remotion`, `ass` or null), filler-cleaning flag, the cleaned words actually drawn and an unavailable reason; and the list of disabled heuristics. The legacy top-level `duration` keeps its meaning (requested content seconds). Words are mapped by one function for one or many intervals; a word straddling a boundary keeps its inside part; metadata such as speaker is carried through. `crop_keyframes[].t` is validated in content-relative seconds against the content duration and handed to the cropper unchanged, with `clip_start=0`.
- **B1-3.** After cut, framing, captions and loudness, the content file is probed: video end within tolerance of the requested content, audio present when the source had it, audio and video ends in agreement. After bookends, the composed file is probed again: video stream present, exact format dimensions, audio present when the source had it, duration equal to content plus each bookend's asset duration minus its reported overlap, and A/V agreement. Tolerance is derived per render (`timing_tolerance`): per cut one source frame plus one AAC frame, plus one output frame; per join one output frame plus one AAC frame; A/V one output frame plus two AAC frames plus per-cut frame slack. The basis string is in the result. `concat_outro` gained an additive `report` dict that records the branch actually taken (`xfade_acrossfade`, `xfade_audio_concat`, `hardcut_soft_audio`, `hardcut`), the requested fade, the applied overlap (0 for hard cuts), both input durations and the probed output; its return value and behaviour for legacy callers are unchanged. Any verification failure raises `ExactRenderVerificationError` before the output path is touched. The proven file is then published with a size-checked copy to a sibling temporary name and one `os.replace`.
- **B1-4.** `handle_create_clip` passes `timing_mode` through, keeps the legacy `start_second`/`end_second` requirement for legacy requests, treats them as optional in exact mode, and in exact mode refuses an asset name that `asset_store.resolve` could not turn into an existing file (legacy behaviour, where an unresolved asset silently becomes none, is unchanged). The result JSON is emitted as returned. Batch, preview, CLI, Studio routes and MCP tools do not enable the mode. `src/models/index.ts` adds `TimingMode`, `RenderTimeline` and related types and optional `timing_mode`/`render_timeline` on `ClipResult`.

## Deviations and decision requests

No blocking decision is open. Delegated choices the lead should scrutinize:

1. **Audio-only sources are refused in exact mode** rather than routed through the audiogram renderer. Decided per the handoff's explicit option; legacy calls keep the audiogram.
2. **Legacy bounds in exact mode** are ignored for cutting and reported as the bounding min/max of the intervals (`start_second`, `end_second`), so a reversed sequence reports `[2.0, 7.0]`. Existing readers that store bounds get a truthful bounding range; the ordered sequence lives only in `render_timeline.segments`.
3. **Retained words** in the result are the supplied source-absolute words that touch any kept interval (`words.source`), plus `source_count` for the full list. The whole transcript is not echoed back, keeping the receipt bounded; the caller still holds the full list and 1B.2 can persist it.
4. **Tolerance** is derived from the probed source fps, the output fps and the cut/join counts as documented in `timing_tolerance`; measured values on the fixtures were content 2.04 s for 2.0 s requested (two cuts at 25 fps) and audio 8 to 25 ms longer than video after resampling. Frame stepping is not claimed to be exact anywhere; the timeline says so.
5. **Bridge strictness** is asymmetric on purpose: exact mode rejects an asset that did not resolve and accepts missing bounds; legacy keeps its `KeyError` on missing bounds and its silent drop of unresolved assets.
6. **Transition autofix environment override** (`PODCLI_TRANSITION_AUTOFIX_PASSES`) is ignored in exact mode, since the pass re-encodes and blurs content.
7. **Publish path** reuses the legacy in-process `_reserve_output_path` naming, so a second exact render of the same title in one process gets a suffix and a later process replaces its own earlier output atomically. Operation-owned staging directories and never-replace semantics are 1B.2 scope.
8. **Diff shape**: the legacy planning block in `clip_generator.py` is re-indented under `else`; its statements are unchanged, which the retained legacy tests, the preview parity script and the stubbed "legacy still sorts and snaps" test corroborate.
